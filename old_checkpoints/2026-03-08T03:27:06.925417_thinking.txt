Looking at the experience data, the problem is absolutely clear:

**The bot NEVER casts any spells for the entire 24+ second episode.** Both champions stay at 100% HP, 0 kills, 0 deaths, 35 gold. All abilities (Q0W0E0R0) are ready the ENTIRE time. The enemy is within 400-900 units consistently (well within Q range of 1050).

From the history, this same problem has persisted across ALL iterations. The root cause: **the dodge/movement code always executes before spell casting, and there are always projectiles visible, so the bot perpetually moves without ever attacking.**

Looking at the current policy flow:
1. Retreat check (HP < 0.15) - doesn't trigger
2. R execute check - doesn't trigger (enemy at 100%)
3. Close distance check (enemy_dist > 1100) - doesn't trigger (enemy is ~800)
4. Cast tick check (tick % 3 == 0) - only 1/3 ticks cast, but...
5. Dodge imminent projectile (15 < pdist < 200) - THIS catches projectiles every frame
6. Reposition - this runs on non-cast, non-dodge ticks

The `imminent_proj` filter uses 15 < pdist < 200. Looking at projectile data, many projectiles have dx/dy like (222,377) = dist 437, too far. But some have values like (-206,67) = dist 216, still > 200. Actually most are 200-400+ range.

Wait - the bot IS at 100% HP the whole time. It's not getting hit either. So the dodge IS working but it's ALSO preventing any attacks. The bot just dances around without ever dealing damage.

The fix: **ALWAYS cast Q when it's ready and enemy is in range, BEFORE checking dodge.** Q is an instant-cast skillshot - cast it then dodge next tick. The spell cast should be the absolute highest priority when in combat range.

Also, the bot needs to close distance more aggressively - it hovers at ~800 range but should get closer to ensure Q lands.

Key changes:
1. Q cast is PRIORITY 0 - always cast when ready and in range
2. W cast is PRIORITY 1
3. Dodge only AFTER casting
4. Much tighter dodge threshold (< 150 only)
5. More aggressive closing
6. Use auto-attacks when very close
